# React 基础专栏 21 天正文驱动学习日计划

适用专栏：[React 18 基础版 - usehook](https://reactzm.usehook.cn/)  
目标目录：`React/base`  
学习周期：21 天  
建议投入：每天 1.5-2.5 小时

## 计划调整说明

这版计划基于 Playwright 阅读专栏代表章节正文后重写。正文里反复强调的重点不是“背 API”，而是：

- React 学习不能停留在碎片语法，要理解知识如何拼装成项目。
- React 更像 UI 库，它引导我们思考如何构建应用。
- 组件化是比模块化更贴近 UI 的组织方式。
- 封装的关键是找相同点和不同点，相同逻辑留在内部，不同部分通过参数、props、children 或 render props 暴露。
- 数据驱动视图的核心是把 UI 变化抽象成数据变化。
- 开关思维要求改变 UI 的方式尽量简单，最好能落到清晰的状态和简洁的 set 操作。
- 组件拆分要看代码规模、重复 UI、数据归属，尤其要判断共享数据最近的父组件。
- useEffect 是难点，要围绕副作用、依赖、清理、闭包旧值反复练。
- 性能优化要先理解 React 更新机制，再使用 memo、useCallback、useMemo。

所以这份日计划把每天的重点改成：**读正文 -> 复述思想 -> 做小练习 -> 产出判断标准 -> 记录旧理解修正**。

## 每日固定动作

- 读正文：只抓作者这一章到底想修正什么理解。
- 做练习：不要只看案例，必须自己在 `React/base` 下写小 demo 或伪代码笔记。
- 写产出：当天至少留下 1 个可复查结果。
- 纠正记录：写清楚“我原来怎么想，现在怎么想”。

## 第 1 天：建立 React 学习地图

- 03、前言

正文重点：

- 不要把 React 学成碎片语法。

## 第 2 天：组件化不是简单拆文件

学习章节：

- 10、组件化

正文重点：

- 组件化是建立在模块化之上的 UI 组织方式。
- 页面、局部区域、甚至单个 HTML 元素都可以放进组件化思维里理解。
- 组件不是越多越好，关键是能不能让 UI 结构更清楚。

练习任务：

- 找一个常见页面，例如个人资料页、商品列表页、登录页。
- 不写代码，先画出组件树。
- 标出哪些组件只是展示，哪些组件可能持有状态。

今日产出：

- 一张组件树草图。
- 写出 3 条你判断“这里应该拆组件”的理由。

## 第 3 天：封装思考

学习章节：

- 11、封装思考

正文重点：

- 封装的底层逻辑是：找相同点和不同点。
- 相同部分留在内部，不同部分通过参数、属性或插槽式结构传入。
- 自定义组件本质上是对标签和 UI 结构的封装。

练习任务：

- 设计一个 `List` 的封装方案。
- 先写出 3 个不同列表场景：用户列表、文章列表、通知列表。
- 分析它们相同在哪里，不同在哪里。

今日产出：

- 一份“相同点 / 不同点”表。
- 写出你会暴露哪些 props，以及为什么。

## 第 4 天：数据驱动视图

学习章节：

- 12、数据驱动视图

正文重点：

- 传统方式偏向获取元素并操作元素。
- React 要把 UI 变化抽象成数据变化。
- 弹窗显示隐藏这类交互，本质上可以抽象成 boolean 状态。

练习任务：

- 设计一个弹窗交互。
- 分别写出“传统 DOM 操作思路”和“React 数据驱动思路”的流程。
- 不要求完整代码，重点是流程对比。

今日产出：

- 一张对比笔记：操作 DOM vs 改变状态。
- 用自己的话解释：为什么 React 中要先找状态？

## 第 5 天：组件最小粒度与状态归属

学习章节：

- 13、组件最小粒度原则

正文重点：

- 组件过大、阅读困难时要考虑拆分。
- 类似 UI 多次出现时要考虑封装。
- 数据归属是拆组件时最容易忽略、也最重要的判断。
- 多个组件共享数据时，优先考虑最近的共同父组件。

练习任务：

- 画一个 TodoList 的组件树。
- 标出 `todos`、`filter`、`editingId` 分别应该属于哪个组件。
- 写出你为什么这样放。

今日产出：

- 一张“组件树 + 状态归属图”。
- 总结一句判断标准：共享状态应该放在哪里？

## 第 6 天：开关思维

学习章节：

- 14、开关思维
- 21、条件判断

正文重点：

- 开关思维是数据驱动视图的进一步提炼。
- UI 变化要尽量落到简单的数据变化。
- 改变数据的方式越简单越好，理想情况下是一行明确的 set 操作。

练习任务：

- 设计一个移动端列表页状态：下拉刷新、上拉加载、空列表、错误、弹窗。
- 为每个 UI 状态设计一个状态字段。
- 检查这些状态是否有冲突或重复。

今日产出：

- 一份“UI 状态 -> 数据开关”的映射表。
- 写出 2 个你以前可能会用复杂逻辑处理、现在可以用状态开关表达的场景。

## 第 7 天：Props 与组件参数

学习章节：

- 16、Props
- 17、实践：封装头像组件

正文重点：

今日产出：

## 第 8 天：children 与容器组件

- 18、children

练习任务：

## 第 9 天：Render Props 与列表封装

- 19、Render Props

## 第 10 天：useState 与内部状态

学习章节：

- 23、useState
- 25、实践：列表操作

正文重点：

- 组件不仅可以通过 props 接收外部数据，也可以通过 useState 管理内部状态。

- 列表增删改是练习状态更新的高频场景。

## 第 11 天：父子组件通信

学习章节：

- 24、父子组件通信

正文重点：

- 父组件通过 props 把数据传给子组件。
- 子组件通过调用父组件传入的函数，把内部行为通知父组件。
- 子组件不应该直接拥有不属于自己的共享状态。

练习任务：

- 设计一个搜索框和列表组件。
- 父组件保存 keyword，搜索框只负责输入，列表只负责展示过滤结果。

今日产出：

- 一张父子数据流图。
- 写出：子组件“通知父组件”和“修改父组件状态”有什么区别？

## 第 12 天：自定义 Hook

学习章节：

- 26、自定义 hook

正文重点：

- 自定义 hook 本质上仍然是函数封装。
- 它和普通函数的区别是内部可以使用 React Hook。
- 它用于复用状态逻辑，而不只是复用工具函数。

练习任务：

- 从 TodoList 或搜索案例里找一个状态逻辑。

今日产出：

## 第 13 天：useRef

学习章节：

- 27、useRef
- 28、实践：数组序列问题

正文重点：

- useRef 声明的变量不会触发组件重新渲染。
- ref 适合保存需要跨渲染保持、但不用于直接驱动 UI 的值。
- 它和 useState 的区别要在“是否触发渲染”上理解。

练习任务：

- 设计 3 个场景：输入框聚焦、保存定时器 id、记录上一次值。
- 判断每个场景用 state 还是 ref。

今日产出：

- 一份 state/ref 对比表。
- 写出：如果把 ref 用成 state，会出现什么问题？

## 第 14 天：useEffect 基础

学习章节：

- 29、useEffect 1
- 30、基于 useEffect 封装自定义 hook

正文重点：

- useEffect 是 React 中较难理解的 hook。

- effect 和 hook 封装结合时，要先分清副作用边界。

练习任务：

- 列出 5 个副作用场景：请求、订阅、事件监听、定时器、手动 DOM。

今日产出：

## 第 16 天：闭包对 useEffect 的影响

学习章节：

- 33、闭包对 useEffect 的影响
- 34、再说闭包陷阱

正文重点：

- 函数组件和 useEffect 很容易形成闭包。

练习任务：

## 第 21 天：useCallback、useMemo 与外部 Store

学习章节：

- 45、useCallback
- 46、实践：re-render 优化
- 47、useMemo
- 48、实践：TodoList 优化
- 49、useLayoutEffect
- 50、useSyncExternalStore

正文重点：

- useCallback 配合 memo 处理函数引用变化。
- useMemo 缓存计算结果，结果是函数时接近 useCallback。
- useLayoutEffect 和 useEffect API 相似，但执行时机不同。
- useSyncExternalStore 面向 React 外部数据源，例如浏览器 API、第三方 store、全局变量。

练习任务：

- 复盘一个 TodoList 优化案例。
- 标出哪里是函数引用问题，哪里是计算结果缓存问题，哪里其实不需要优化。
- 设计一个订阅 `window.innerWidth` 的外部数据源方案。

今日产出：

- 一份性能优化判断清单。
- 一篇 300 字总结：我现在如何理解 React 基础？

## 第一轮完成标准

21 天后，不要求你完全掌握所有细节。只要你能比较自然地回答下面问题，就说明第一轮有效：

- 为什么 React 不能只按 API 碎片学习？
- 拆组件时如何同时看 UI、封装和数据归属？
- props、children、render props 分别暴露了什么变化点？
- state、ref、context 分别解决什么问题？
- useEffect 什么时候该用，什么时候不该用？
- 闭包旧值为什么会在 effect 中出现？
- memo、useCallback、useMemo 分别优化什么？
- useSyncExternalStore 为什么不是普通 useEffect + useState 的简单替代？

真正重要的不是第一遍就全懂，而是你开始拥有一套稳定的纠错方式：每学一个概念，都能回头检查自己过去项目里的写法是否准确。
